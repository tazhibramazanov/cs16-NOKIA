# Нативный порт CS 1.6 E52 для Symbian S60 3rd FP2

Это каталог исходников нативного Symbian C++ движка (не Java MIDlet). Цель — получить
на Nokia E52 вместо MIDP-буфера прямой вывод в экран (DSA), RGB565, ARM11, 30–40 FPS.
Java-версия (`src/core`, `src/midp`), ПК-версия (`src/pc`) и `СОБРАТЬ.bat` остаются эталоном и **не изменяются**.

## 1. Что нужно для сборки

- **S60 3rd Edition Feature Pack 2 SDK** с компилятором **GCCE** (ARM11 / ARM1136J-S).
  Установите SDK в любой каталог, например `C:\Symbian\9.2\S60_3rd_FP2`.
- Утилиты из SDK: `bldmake`, `abld`, `makesis`, `signsis` — обычно лежат в
  `Epoc32\tools`. Они должны находиться в `PATH` или быть доступны через `--bldmake`,
  `--abld`, `--makesis`, `--signsis`.
- Переменная окружения `EPOCROOT` (или `EPOC32`) с путём к корню SDK. `build_symbian.py`
  также ищет SDK сам: `C:\Symbian\9.2\S60_3rd_FP2`, `C:\S60\devices\...`, `C:\Nokia\Devices\...`.
- Сертификат и ключ `cert/cs16e52_cert.pem`, `cert/cs16e52_key.pem`. Их создаёт обычный
  `build.py` на шаге подписи Java-установщика; можно указать свои через `--cert` и `--key`.
  Тип подписи — self-signed, поэтому в `.mmp` заявлены только пользовательские capabilities:
  `LocalServices NetworkServices ReadUserData WriteUserData UserEnvironment`.

**На текущем компьютере SDK отсутствует:** переменные `EPOCROOT`/`EPOC32` не заданы,
утилиты Symbian и GCCE не установлены. Поэтому собрать и проверить ARM-бинарник здесь
**невозможно**; проверяются только скрипты, форматы данных и исходники. При отсутствии SDK
`build_symbian.py` печатает понятное сообщение, возвращает код 0 — обычная сборка `.jar`/`.exe`
продолжается без изменений.

## 2. Подготовка ресурсов (импорт)

Конвертеры из `conv/` создают из вашей копии CS 1.6 файлы в `res/` и `build/`:

| Что | Файлы |
|---|---|
| карты | `*.cse` (CSE3) |
| навигация ботов | `*.nv` |
| модели / анимации | `*.m3` (CSM2), `*.a3` (CSA3), `mdltex.bin` (CST1) |
| HUD, шрифты | `hud.bin` (HUD1), `f1.fnt`, `f2.fnt` (FNT1) |
| звуки | `snd/*.wav` (11025 Гц, 8 бит, mono) |
| небо | `sky_<name>.png` — полоса 128×640: пять граней по 128×128 в порядке rt/lf/bk/ft/up |

Импорт запускается автоматически из `build.py` (через `build_symbian.py`), вручную:

```
python src/symbian/tools/import_assets.py
```

Источники по умолчанию — `res/` и `build/`, приёмник — `build/symbian/data/cs16/`
(на телефоне это `!:\data\cs16\`). Все файлы копируются **байт в байт** и только для чтения;
исходные `res/`, `build/`, а также `src/core`, `src/midp`, `src/pc` не модифицируются.
`sky_*.png` дополнительно превращается в `sky_*.rgb565`: 5·128·128 слов RGB565 в
little-endian, именно в том порядке, в котором читает `CMap::LoadSkyL()`.
Декодер PNG реализован на чистом Python (`zlib` + `struct`): Pillow не нужна;
поддерживаются серый, RGB, палитра, серый+alpha, RGBA, глубины 1/2/4/8/16, фильтры 0–4
и Adam7.

Вручную можно задать источники и папку данных:

```
python src/symbian/tools/import_assets.py --source res --source build --dest build\symbian\data\cs16
```

Если файлов нет, скрипт просто сообщает, что нужно сначала запустить `build.py`, и ничего не ломает.

## 3. Сборка

Обычный путь — один раз запустить `СОБРАТЬ.bat` (или `python build.py`). После `.jar`, `.jad`,
Java-`.sisx` и `.exe` вызывается нативная сборка. Её результат становится основным установщиком
`CS16_E52.sisx` на рабочем столе; Java-установщик при этом сохраняется как `CS16_E52_JAVA.sisx`.
Если SDK не найден, обычный `CS16_E52.sisx` остаётся Java-версией.

Ручной вызов:

```
set EPOCROOT=C:\Symbian\9.2\S60_3rd_FP2\
python src\symbian\tools\build_symbian.py --sdk "C:\Symbian\9.2\S60_3rd_FP2" --output build\symbian
```

Выполняется последовательно:

```
bldmake bldfiles
abld build gcce urel
makesis CS16_E52_generated.pkg CS16_E52.sis
signsis CS16_E52.sis CS16_E52.sisx cs16e52_cert.der cs16e52_key.pem
```

Флаги компилятора заданы в `group/cs16e52.mmp`:
`-O3 -march=armv6 -mtune=arm1136j-s -fno-exceptions -fno-rtti`.
Цель — `cs16e52.exe` (UID `0x2003C516`), установщик — `CS16_E52.sisx`.

## 4. Установка на телефон

1. Скопируйте `CS16_E52.sisx` (нативный пакет) на Nokia E52 (USB, Bluetooth или карта памяти) и откройте.
2. Подтвердите self-signed установку. Пакет ставит `cs16e52.exe` в `!:\sys\bin\`,
   ресурсы — в `!:\resource\apps\` и `!:\private\10003a3f\import\apps\`, данные —
   в `!:\data\cs16\`. Удаление `.sisx` с телефона не удаляет папку данных.
3. В меню приложений найдите «CS 1.6 E52». Если нужны только совместимость и MIDP,
   используйте `CS16_E52_JAVA.sisx` / `CS16_E52.jar`.

## 5. Ограничения DSA и нативного рендера

- `CDirectScreenAccess` захватывает весь экран. Входящий вызов, системное меню, таймер
  или другой полноэкранный клиент может вызвать `Abort()`; движок должен перехватить
  `Restart()` и продолжить кадр. Одновременного окна с Avkon-интерфейсом нет.
- DSA работает только на устройствах с поддержкой direct screen access и экраном RGB565
  (`EColor64K`). На touch-моделях без клавиатуры управление не адаптировано.
- Буфер кадра — собственный `TUint16*` 240×320 (портрет) или 320×240 (ландшафт);
  масштабирование и буферы MIDP не используются. Системные диалоги поверх DSA не рисуются.
- При работе с DSA нельзя вызывать блокирующие операции в потоке UI: сеть, WAV и таймер
  вынесены в `CActive`/`RTimer`, иначе телефон покажет «не отвечает».
- Пакет подписан пользовательским ключом: capabilities ограничены списком выше.
  Для устройств с более строгой политикой потребуется сертификат, выданный Symbian Signed.
- Точность и поведение графики/физики соответствуют Java-эталону; DSA ускоряет вывод,
  но не добавляет новых игровых возможностей.

## 6. Управление (Nokia E52)

| Клавиша | Действие |
|---|---|
| 2 / 8 / 4 / 6 | вперёд / назад / влево / вправо |
| джойстик | поворот / осмотр |
| 5 / центр джойстика | выстрел |
| 1 | прыжок |
| 3 | присесть |
| 7 | перезарядка |
| 0 | использовать / обезвредить бомбу |
| 9 | следующее оружие |
| \* | прицел / глушитель |
| # | покупка |
| зелёная клавиша вызова | walkie-talkie (нажать и говорить) |
| левая софт-клавиша / C | пауза и настройки |
| правая софт-клавиша | счёт |
| EAknSoftkeyExit / системная «Назад» | выход / пауза |

Все игровые клавиши переназначаются в меню «Settings → Keys». В меню программы
доступен только «Exit» — остальные настройки рисует сам движок.

## 7. Проверки без SDK

Эти проверки не заменяют GCCE, но ловят опечатки, пропущенные include'ы и синтаксические ошибки:

```
python src/symbian/tools/gen_data.py --check
python src/symbian/tools/check_sources.py
python -m pip install ziglang
python src/symbian/tools/syntax_check.py
```

`gen_data.py --check` сверяет `inc/LangData.h` и `inc/WeaponData.h` с эталонными
`src/core/cs/Lang.java` и `Wp.java`; без `--check` скрипт пересоздаёт эти заголовки.
`syntax_check.py` компилирует каждый `.cpp` только в режиме `-fsyntax-only`, используя
минимальные заглушки из `tools/symbian_stubs/`. Настоящие заголовки S60 доступны только
в SDK; поэтому итоговый `.exe` и подписанный `.sisx` можно получить лишь на машине
с установленным S60 3rd FP2 SDK + GCCE.
